# 部署与排错

本章说明 Sky 导航站如何部署到 GitHub Pages、Cloudflare Pages、Vercel 和 Netlify，并解释项目页常见 404 的排查顺序。

## 通用静态构建

项目统一使用 npm。部署前先执行以下命令；静态网站产物会生成在 `dist/public`。

```bash
npm install
npm run check
npm run build:static
```

`vite.config.ts` 使用 `base: "./"`，因此构建后的 CSS 和 JavaScript 使用 `./assets/...` 相对地址。这适合 GitHub Pages 的仓库子路径，也适合多数静态托管平台。

若要脱离当前托管环境部署，请把显著图片下载到 `client/public/assets/`，然后在 `Home.tsx` 与 `client/index.html` 中使用 `./assets/...` 地址。不要在外部部署中继续依赖 `/manus-storage/...` 图像地址。

## GitHub Pages：唯一的 gh-pages 工作流

项目只保留 `.github/workflows/deploy-gh-pages.yml`。当 `main` 或 `master` 推送时，它会执行依赖安装、类型检查、静态构建，并确认 `dist/public/index.html`、`.nojekyll` 与 `assets/` 存在；随后将构建产物发布到 `gh-pages` 分支根目录。

| 步骤 | 在哪里做    | 操作                                                                           |
| ---- | ----------- | ------------------------------------------------------------------------------ |
| 1    | 本地终端    | `git add .`、`git commit -m "Deploy site"`、`git push -u origin main`          |
| 2    | GitHub 仓库 | **Settings → Pages** 选择 **Deploy from a branch → `gh-pages` → `/(root)`**    |
| 3    | GitHub 仓库 | **Settings → Actions → General** 允许工作流拥有 **Read and write permissions** |
| 4    | GitHub 仓库 | 在 **Actions** 确认 “Deploy Sky Navigation to GitHub Pages” 成功               |

工作流使用自动提供的 `GITHUB_TOKEN` 与 `contents: write`，不需要 `PAGES_DEPLOY_TOKEN` 或部署密钥。

```bash
# 本地检查并触发唯一的 gh-pages 发布工作流
npm run publish:gh-pages

# 查看最近发布状态
npm run publish:status
```

### GitHub 项目页的两类 404

项目页地址类似 `https://用户名.github.io/仓库名/`。资源路径与前端路由要分别检查。

| 现象                                          | 根因                                                             | 处理方式                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| CSS 或 JS 返回 404                            | Vite 生成了根路径资源地址                                        | 检查 `vite.config.ts` 的 `base: "./"`，构建后确认 `index.html` 为 `./assets/...` |
| 页面带本项目自己的 “Page Not Found / Go Home” | `index.html` 与 JS 已加载，但 Wouter 没有识别 `/sky-navigation/` | 保留 `client/src/App.tsx` 中 `getRouterBase()` 和 `WouterRouter base={base}`     |
| 页面是 GitHub 原生 404                        | Pages 分支、目录、仓库公开性或传播有问题                         | 检查 Pages 设置、`gh-pages` 根目录和最新工作流                                   |

> 不要删除 `getRouterBase()`，也不要把 `/sky-navigation` 无条件用于所有域名。该函数只在 `*.github.io` 的项目页路径下启用；本地、Manus 域名和自定义域名仍从 `/` 开始。

更新发布后，请使用无痕窗口、`Ctrl/Cmd + Shift + R`，或附加 `?v=时间戳` 后访问 `https://zhixiaotx.github.io/sky-navigation/`。浏览器可能缓存旧 JavaScript；仅凭 HTTP 200 或 HTML 标题无法确认客户端路由已经显示首页。

## Cloudflare Pages

在 **Workers & Pages → Create application → Pages → Import an existing Git repository** 中选择仓库。构建命令填写 `npm run build:static`，输出目录填写 `dist/public`。该静态站不需要环境变量；向主分支推送后会自动重新构建。[1]

## Vercel

导入仓库后保留项目根目录的 `vercel.json`。该文件已经指定 `npm run build:static`、`dist/public` 和 SPA 回退规则；确认根目录无误后即可部署。单页应用的深链接需要重写到 `index.html`，项目配置已经包含该规则。[2]

## Netlify

项目根目录的 `netlify.toml` 已指定构建命令、发布目录和 `/* → /index.html` 的 SPA 重定向。导入仓库后确认构建命令为 `npm run build:static`、发布目录为 `dist/public`。也可以本地构建后，把 `dist/public` 文件夹拖入 Netlify 的手动部署区域。[3]

## 快速排错清单

1. 运行 `npm run check` 和 `npm run build:static`。
2. 检查 `dist/public/index.html`、`dist/public/assets/` 和 `.nojekyll`。
3. 在 GitHub Pages 中确认来源是 `gh-pages` 的 `/(root)`。
4. 查看唯一发布工作流的最近运行状态。
5. 访问项目页时，区分 GitHub 原生 404 与项目自己的 NotFound 页面。
6. 对项目自己的 NotFound，检查 `App.tsx` 的 Wouter 基路径；对资源 404，检查 Vite 相对路径。
7. 用无痕窗口或查询参数重新访问，避免旧 JavaScript 缓存造成误判。
